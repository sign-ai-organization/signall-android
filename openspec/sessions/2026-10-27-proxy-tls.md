# El APK `demo` habla `wss://` y demuestra el rechazo del texto en claro

**Fecha:** 2026-10-27, madrugada · **Rama:** `main`

## Qué llegó

El otro lado de [`../../signall-backend/docs/plan-proxy-tls.md`](../../../signall-backend/docs/plan-proxy-tls.md):
el backend ya tiene un Caddy terminando TLS en el 443, y la app tenía que dejar de hablar
`ws://` para que el requisito RF-INT-COM-06 se cumpliera de punta a punta. La app y el
puente Kotlin ↔ JS **no se tocaron**: `SignAiWebSocketClient` ya soportaba `wss://` y el
manifiesto ya apuntaba a `@xml/network_security_config`. El cambio es de build.

## Qué se hizo

| Archivo | Qué cambió |
|---|---|
| `app/src/demo/res/xml/network_security_config.xml` | **Nuevo.** `cleartextTrafficPermitted="false"` y `trust-anchors` con `system` + `user`. Es el único build type que puede prohibir el texto en claro **y** confiar en la CA de laboratorio a la vez |
| `app/build.gradle.kts` | `buildTypes { create("demo") { … } }`: `initWith(release)`, firma de `debug`, `isDebuggable = true` y `BACKEND_WS_URL` en `wss://127.0.0.1:8443/ws/translate`. Igual que `release`, la propiedad de build solo acepta una dirección que empiece con `wss://` |
| `tools/verificar-tiempo-real.sh` | Variante TLS del chequeo del teléfono: además del 8080, prueba `https://127.0.0.1:8443` y avisa si la CA del laboratorio no está en el host |
| `AGENTS.md`, `docs/SISTEMA.md` | El comando de demo con `wss://`, `adb reverse tcp:8443 tcp:443` y el nombre del certificado |
| `docs/historia/CONTRASTE-APPvsDOCUMENTOS.md` | A3 reescrito: ya no dice "no cifrado", y la verificación queda con hook concreto (logcat + captura) |

**Por qué un build type nuevo y no `debug`:** desde la API 24 Android no confía en las CA
que instala el usuario salvo que el `network_security_config` de la app lo declare, y
`debug` permite texto en claro. Con `debug` se puede enseñar el cifrado, pero no se puede
probar que la app **rechaza** un `ws://`.

**Por qué el 8443:** `adb reverse tcp:443 tcp:443` falla en el teléfono
(`cannot bind listener: Permission denied`). Se mapea `tcp:8443 → 443` del host; el
certificado no depende del puerto.

## Qué se verificó

| Prueba | Resultado |
|---|---|
| `./gradlew assembleDemo installDemo` | instala y arranca |
| `adb logcat -s SignAiNet` | `sesión abierta: wss://127.0.0.1:8443/ws/translate (TLS)` |
| APK `demo` contra el 8080 en claro | `CLEARTEXT communication … not permitted` |
| Frase de punta a punta | `segment 0/1 -> HOLA,GRACIAS`, `frase #2: 40ms`, `representado: 2 señas en 4096ms` |
| `tools/verificar-tiempo-real.sh` | `ok el proxy responde con TLS — host con la CA del laboratorio; teléfono por adb reverse tcp:8443 tcp:443` |

**La latencia no se movió** por el TLS: caché 40–41 ms contra 86 ms de la línea base sin
cifrar, y LLM 325–370 ms contra 345 ms. El handshake ocurre una vez, al abrir la app.

## Lo que hay que saber antes de tocar esto

- **El APK `demo` comparte `applicationId` con `debug` y lo reemplaza en el teléfono.**
  Para volver a medir con `debug`: `./gradlew installDebug`.
- **La CA del laboratorio se instala a mano** (Ajustes → Seguridad → Cifrado y
  credenciales → Instalar un certificado → Certificado de CA). Android 11 exige pantalla
  de bloqueo, y MIUI a veces no muestra el archivo si no termina en `.crt`.
- **Cambiar de camino (USB ↔ Wi-Fi) no obliga a recompilar** si se pasa la dirección por
  propiedad de build, pero la de `demo` por defecto es la de USB.
- **El APK de `release` no sirve todavía**: sigue apuntando a `wss://backend.invalid`.
